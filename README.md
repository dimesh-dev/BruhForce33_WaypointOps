# Waypoint

A sketch-inspired, interactive **Designathon-only** delivery planning prototype for Tech-Triathlon 2026. Built with **Next.js App Router, React, TypeScript and Tailwind CSS**. Seven original watercolor/pencil illustrations follow the user's supplied visual reference.

## Run locally

```bash
npm install
npm run dev
```

Open the localhost address printed in the terminal (default port 3000). `npm run build` produces the production build; `npm start` serves it. Node.js 20.9+ is required by the installed Next.js version. Fonts are bundled locally; no API keys or external services are needed.

## Explore

1. Select routes on the schematic map, change depot, toggle traffic, and inspect a route.
2. Search/filter deliveries, open an order, and export the current CSV view.
3. Review the mall-window exception, record a reason and defer the order.
4. Publish the representative dispatch plan after reviewing operating constraints.
5. Switch to **Loader**, see plan v2, check reverse loading order, report a shortfall and mark readiness.
6. Switch to **Driver**, simulate offline, capture receiving contact/quantity/proof, and refresh. The pending record remains on this device. Reconnect to update the shared order.
7. Switch to **Store manager**, confirm the received delivery or report an issue. Use the store picker to inspect the deferred mall order. Place a Fresh order and explore the after-cutoff state.
8. Use the footer guided tour or Prototype guide. Reset demo data from the guide to repeat the sequence.

## Scope and data honesty

The network totals match the booklet. Six seed orders, three routes, ETAs, driver names, vehicle capacities, performance metrics, geographic positions and forecast-looking charts are **illustrative**; no shared CSVs were supplied. The `WP-` demo IDs are not official dataset identifiers. The map is schematic.

The fixed review scenario uses Monday 28 September 2026 in Asia/Colombo. It compresses operational stages so a reviewer can traverse all roles. Actions persist to localStorage in the same browser. The connection toggle simulates an offline state after the app loads; there is no backend, cross-device synchronization, service worker, real routing or optimization engine, telemetry, authentication or trained forecast. Photo/signature capture is represented by a proof note.

The store picker is for reviewers, not an authorization model. Loader readiness does not implement production shortfall blocking. Future synchronization conflicts, immutable proof storage and constraint validation are documented for the later Hackathon phase. No Hackathon or Datathon deliverables have been implemented or claimed.

## Code organization

`src/app` owns the Next.js page/layout and shared visual system. `src/components` separates the workspace shell, interactive map, order table, role experiences, insights, dialogs and reusable controls. `src/lib` contains typed demonstration records, shared types and the hydration-safe local persistence hook. Tailwind utilities complement the custom sketch-inspired component styles.
